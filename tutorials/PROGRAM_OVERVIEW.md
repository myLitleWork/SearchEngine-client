# Обзор программы SearchClient

## Что это за программа

**SearchClient_asio** — настольная программа для Windows, с помощью которой можно искать служебные телеграммы (входящие и исходящие) на поисковых серверах, просматривать их текст и связанные сведения, сохранять файлы и приложения на компьютер, а также выполнять ряд служебных операций по загрузке данных на сервер.

Текущая версия в сборке отображается в заголовке окна как `SearchClient_asio vX.Y.Z`.

Программа работает как **клиент**: сами базы поиска хранятся на серверах. На компьютере пользователя программа держит локальные настройки, временные результаты текущего поиска и файлы авторизации.

## Для кого она предназначена

Программа рассчитана на сотрудников, которые работают с учётом и поиском телеграмм (шт.): находят нужные документы по номеру, содержанию, адресовке и другим полям, просматривают маршрут документа, приложения и подтверждения, выгружают файлы для дальнейшей работы.

Предполагается базовое умение пользоваться Windows (папки, выбор файлов, подключение сетевых ресурсов). Знание программирования не требуется.

Для полноценной работы обычно нужны:

- доступ к поисковому серверу (или нескольким серверам) по сети;
- входящая в релиз временная заглушка авторизации `admin984.bin` рядом с программой;
- подготовленная организацией конфигурация серверов и поиска в `Settings.db3`.

## Что программа умеет

- подключаться к одному или нескольким поисковым серверам за выбранный год;
- автоматически включать временного пользователя `admin` по файлу `admin984.bin`;
- искать телеграммы по тексту (полнотекстовый поиск) или по полям (режим SQL);
- ограничивать число ответов с каждого сервера;
- объединять результаты с нескольких серверов в одной таблице;
- просматривать текст выбранной телеграммы с подсветкой слов запроса;
- открывать детали строки: путь документа, список приложений, подтверждения (для исходящих);
- сохранять приложения, текст (`.tlg`) или DOCX-версию текста;
- формировать отчёт FastReport и сохранять его в Excel;
- сохранять и применять шаблоны поисковых запросов;
- загружать файлы на сервер «на отправку»;
- загружать разноску;
- сохранять базу для описей;
- сохранять пакет приложений пользователя;
- запускать обновление базы на основном сервере;
- редактировать локальные таблицы настроек (серверы, порты, словари полей и др.).

## Основной порядок работы

1. Запустите программу. Дождитесь появления окна `SearchClient_asio v…`.
2. Убедитесь, что выданный `admin984.bin` лежит рядом с фактически запускаемым EXE.
3. Проверьте адрес сервера (поле IP) и выбранный **год**.
4. Дождитесь надписи вида `Авторизация : …` и статуса успешного подключения — либо нажмите **Подключение**.
5. Перейдите на вкладку **Поиск**.
6. Введите запрос (или включите режим SQL и задайте поле/условия).
7. Нажмите **Поиск** (или `Ctrl+F`).
8. В таблице результатов выберите нужные строки.
9. При необходимости просмотрите текст справа, детали строки (`F12`) или сохраните файлы кнопкой **Сохранить**.
10. При необходимости сформируйте отчёт или выгрузите Excel.
11. Перед закрытием дождитесь окончания сохранения файлов, если оно ещё идёт.

## Интерфейс программы

Главного меню и классической строки состояния нет. Управление — кнопками верхней панели, вкладками и горячими клавишами.

### Верхняя панель

| Элемент | Назначение |
|---|---|
| **Статус:** | Текущее состояние: подключение, поиск, ошибки, число серверов и результатов |
| **Авторизация / Нет авторизации!** | Имя текущего пользователя или отсутствие входа |
| Поле IP (подсказка `Ip (192.168.10.10)`) | Адрес основного (или единственного) сервера |
| **Подключение** | Подключиться к серверам выбранного года и зарегистрироваться |
| Список годов | Выбор года базы поиска |
| **Обновление!** | Запросить обновление базы на основном сервере |
| **Отключение** | Разорвать соединение и отключить основные кнопки работы |

### Вкладка «Поиск»

Основное рабочее место:

- таблица результатов поиска;
- поле запроса и кнопка **Поиск**;
- параметры SQL-поиска (тип Вх./Исх., поле, лимит, точное совпадение);
- флаги **OEM-866**, **SQL**;
- панель сохранения (приложения / tlg / docx, каталог, **Сохранить**);
- **Экспорт отчета**;
- панель шаблонов (**Сохранить**, **Показать/скрыть**);
- область текста телеграммы (RichEdit) с печатью через контекстное меню;
- индикатор прогресса (Gauge) внизу.

### Вкладка «Загрузка»

Служебные операции с файлами и сервером:

- список файлов для загрузки;
- **Добавить файлы** / **Загрузить файлы на отправку**;
- **Сохранить базу для описей**;
- **Загрузить разноску**;
- **Сохранить приложения**;
- журнал операций загрузки.

### Вкладка «Настройки»

Редактор локальной базы `Settings.db3`: вкладки соответствуют таблицам SQLite, содержимое открывается в сетке. Здесь настраиваются серверы, порты по годам, словари полей и ключ `use_f12`.

### Детали строки результата

После выбора строки и открытия панели деталей (`F12`, если разрешено настройками) доступны пункты:

- **Путь:** — маршрут/движение документа;
- **Приложения:** — список вложений с возможностью скачать доступный файл;
- **Подтверждения:** — для исходящих телеграмм.

## Какие данные использует программа

| Данные | Где |
|---|---|
| Настройки серверов, портов, словарей | `Settings.db3` рядом с программой |
| Результаты текущего поиска | `SearchRes.db3` (таблица `res`), очищаются при запуске и перед новым поиском/подключением |
| Начальный адрес сервера (необязательная совместимость) | `SERVER_IP.INI` (одна строка; без файла используется `localhost`) |
| Шаблоны запросов | `Templates.json` |
| Авторизация | входящий в общий пакет `admin984.bin` |
| Шаблон макроса Word для DOCX | `sht.docm` |
| Временные файлы | каталог `%TEMP%` (распаковка ZIP, сессии DOCX) |
| Сетевые серверы | TCP-подключение по host/port из настроек |

Подробнее: [DATA_AND_FILES.md](DATA_AND_FILES.md).

## Важные ограничения

- Без сети и доступного поискового сервера поиск и просмотр содержимого невозможны.
- Без успешной авторизации основные кнопки работы остаются недоступными.
- История введённых запросов хранится только в текущем сеансе (до 9 позиций) и не сохраняется на диск.
- При поиске по нескольким серверам лимит ответов действует **на каждый сервер отдельно**; дубликаты между серверами не удаляются.
- Результаты в локальной базе `SearchRes.db3` — временные: при следующем запуске или новом поиске они очищаются.
- Сохранение в DOCX требует установленного Microsoft Word и файла `sht.docm`.
- Во время пакетного сохранения программу закрыть нельзя.
- Таймауты сети и DOCX заданы в программе и пользователем через интерфейс не меняются.
- Клиент не выполняет групповое разграничение прав. Допустимость чтения,
  скачивания и служебных операций обязан проверять сервер; `use_f12` только
  показывает или скрывает панель деталей.
