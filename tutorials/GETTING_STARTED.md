# Первый запуск и базовая работа

## 1. Что это за программа

**SearchClient_asio** — клиент поиска телеграмм на сетевых серверах. Вы вводите запрос, получаете список найденных документов, просматриваете текст и при необходимости сохраняете файлы на свой компьютер.

Подробный обзор: [PROGRAM_OVERVIEW.md](PROGRAM_OVERVIEW.md).

## 2. Что необходимо для работы

- Компьютер с Windows (программа собрана как Win32-приложение).
- Распакованный релизный комплект программы.
- Сетевой доступ к поисковому серверу (или серверам).
- Временно используемая заглушка авторизации `admin984.bin`, входящая в релиз
  и размещённая рядом с EXE.
- Входящая в релиз `Settings.db3` с готовыми словарями поиска. Перед работой
  организация должна заполнить в ней серверы и порты.

## 3. Нужно ли устанавливать дополнительные компоненты

Для обычного поиска и сохранения `.tlg`/приложений достаточно установленного клиента и доступа к серверу.

Для сохранения в **docx** дополнительно нужны:

- Microsoft Word;
- файл макроса `sht.docm` в каталоге программы (макрос `Обработка_ШТ_2022`).

Отдельно устанавливать RAD Studio, Boost или исходники **не нужно** — это нужно только разработчикам при сборке из исходников.

## 4. Требуется ли база данных

Да, но **локально** и автоматически:

- `Settings.db3` — настройки;
- `SearchRes.db3` — временные результаты текущего поиска.

Пользователю обычно не нужно открывать эти файлы вручную. Основные поисковые данные находятся на сервере.

## 5. Требуется ли сеть

Да. Без подключения к серверу нельзя выполнить поиск, загрузить текст, приложения, путь, подтверждения и служебные операции вкладки **Загрузка**.

## 6. Требуются ли внешние файлы

Чистый релиз уже содержит EXE, необходимые библиотеки, `sht.docm` и начальную
`Settings.db3` со словарями. Отдельно для рабочего места размещаются:

| Файл | Зачем |
|---|---|
| `SearchRes.db3` | локальные результаты; создаётся автоматически, заранее не поставляется |
| `SERVER_IP.INI` | необязательный legacy-файл начального адреса |
| `Templates.json` | шаблоны запросов (если используются) |
| `admin984.bin` | временная заглушка авторизации; входит в релиз |

Не копируйте в каталог клиента публичные/приватные RSA-ключи или старые
`token-HS.bin`: signed-token режим временно отключён. `admin984.bin` является
обязательной частью текущего релиза.

`SERVER_IP.INI` создавать не требуется. Если его нет или он повреждён,
программа без предупреждения использует `localhost`; рабочие адреса берутся из
таблицы `servers` в `Settings.db3`.

Краткая настройка нового рабочего места: [FIRST_START.md](FIRST_START.md).

## 7. Что вы увидите после запуска

1. Откроется главное окно с заголовком вида `SearchClient_asio vX.Y.Z`.
2. Вверху — статус, поле IP, кнопки **Подключение** / **Обновление!** / **Отключение**, список годов.
3. Активна вкладка **Поиск**.
4. Надпись авторизации сначала может быть **Нет авторизации!** (красноватый цвет).
5. Через короткое время (таймер ~1,5 с) программа проверяет `admin984.bin` и,
   если файл существует, показывает **Авторизация : admin** и пытается подключиться.
6. Кнопка **Поиск** и связанные элементы становятся доступны после успешной авторизации/подключения.

Если при старте не удаётся подготовить локальные базы, программа показывает сообщение об ошибке и может не запуститься.

## 8. Какие настройки проверить перед первой работой

1. **Год** в списке годов — тот, по которому нужно искать.
2. **Адрес сервера** в поле IP — если у вас один сервер; при нескольких серверах правильнее проверить таблицы `servers` и `server_ports` на вкладке **Настройки**.
3. Наличие входящего в релиз `admin984.bin` рядом с EXE.
4. При многосерверном поиске — что нужные серверы и порты года включены (`enabled = 1`).

Справочник настроек: [SETTINGS_REFERENCE.md](SETTINGS_REFERENCE.md).  
Многосерверность: [MULTI_SERVER_SEARCH.md](MULTI_SERVER_SEARCH.md).

## 9. Как выполнить основную операцию (поиск)

1. Убедитесь, что `admin984.bin` лежит рядом с EXE, и дождитесь надписи
   `Авторизация : admin`.
2. При необходимости нажмите **Подключение**.
3. В поле запроса введите, например, номер или фрагмент текста.
4. Для поиска по конкретному полю:
   - включите **SQL**;
   - выберите **Вх.** или **Исх.**;
   - выберите **Поле** (например, `Вх/исх №`);
   - при необходимости включите **Точное совпадение**;
   - задайте **Максимальное число ответов**.
5. Нажмите **Поиск** или `Ctrl+F`.
6. Дождитесь заполнения таблицы и обновления строки статуса.

Быстрые клавиши:

- `Alt+F1` — режим SQL, тип **Вх.**, поле номера;
- `Alt+F2` — режим SQL, тип **Исх.**, поле номера;
- `Alt+F3` — раскрыть список полей (если SQL включён).

Подробнее: [functions/02_SEARCH.md](functions/02_SEARCH.md).

## 10. Как проверить результат

Успешный поиск обычно означает:

- в статусе текст вида `Поиск завершён: серверов N, результатов M` (или сообщение о частичном успехе);
- в таблице появились строки;
- при выборе строки справа загружается текст телеграммы (если файл доступен и пользователь авторизован);
- слова запроса в тексте могут быть выделены красным жирным.

Если сервер сообщает об обновлении базы или ни один сервер не ответил — см. [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## 11. Где программа хранит свои данные

Все основные локальные файлы — **в каталоге исполняемого файла** программы:

- настройки и результаты поиска;
- шаблоны;
- IP-файл;
- заглушка `admin984.bin` (если выдана для этого рабочего места).

Временные файлы могут создаваться в `%TEMP%`.

Подробнее: [DATA_AND_FILES.md](DATA_AND_FILES.md).

## 12. Как правильно закрывать программу

1. Дождитесь окончания сохранения файлов (иначе программа предложит дождаться завершения или нажать **Отмена** и не закроется).
2. При желании нажмите **Отключение**.
3. Закройте окно стандартным способом Windows.

Если идёт пакетное сохранение, сначала дождитесь его завершения или нажмите
**Отмена**. После этого программа освобождает панели деталей и завершает
связанные процессы Word/DOCX, если они были запущены через клиент.
