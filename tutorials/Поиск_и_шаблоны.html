Сверено с клиентом 4.3.66 и сервером 0.1.91. Все темы: Все руководства.

1. Два разных источника поиска

Что известно Режим Где ищется
Слова из самого документа SQL выключен В серверном индексе содержимого файлов
Номер, адресовка, исполнитель, дата, краткое содержание или название приложения SQL включён В полях учётных таблиц AutoPad

Краткое содержание в AutoPad и полный текст документа — разные данные. Поиск по тексту не ищет автоматически внутри каждого PDF/DOCX-приложения: он охватывает только файлы, которые сервер включил в текстовый индекс. Поле Название файла прил. ищет имя из карточки, а не содержимое вложения.

Перед любым поиском проверьте год и успешную серверную авторизацию. Новый поиск заменяет предыдущую локальную выборку.

2. Обычный поиск слов в тексте

  1. Снимите SQL. Параметры Тип, Поле, Точное совпадение и пользовательский лимит для этого режима недоступны.
  2. Оставьте OEM-866 включённым: это штатная кодировка запросов к индексу телеграмм. Не меняйте её для расширения поиска.
  3. Введите слова в обычном виде, например проверка связи.
  4. Нажмите Поиск или Ctrl+F и дождитесь завершения.
  5. Выберите строку и прочитайте текст: подсветка помогает ориентироваться, но сама не определяет, почему документ попал в результаты.

В поставляемой конфигурации сервера используется query_word_match = all: должны присутствовать все слова запроса. Они могут находиться в разных местах документа и в любом порядке. Повторение одного слова в запросе не добавляет нового условия.

Сопоставляются целые индексные слова. проверка не означает проверки, проверкой или перепроверка. Поиск не подбирает окончания, исправления опечаток или синонимы. Клиент по умолчанию переводит текстовый запрос в верхний регистр, индекс также нормализует регистр.

Запрос Пример текста При режиме all
проверка связи «Связи посвящена очередная проверка» Найдётся: оба слова есть, порядок не важен
проверка связи «Проверка оборудования» Не найдётся: нет слова «связи»
проверка «Проверки завершены» Не найдётся: другое целое слово
проверка проверка «Проверка завершена» Найдётся: повтор запроса не требует двух вхождений

Условие all настраивается на сервере. Специалист может установить query_word_match = any: тогда достаточно хотя бы одного слова. Галочка Точное совпадение клиента меняет только поиск по таблицам, а не all/any. При нескольких серверах их режимы должны быть согласованы, иначе одинаковый запрос даст выборки по разным правилам.

3. Триммирование: что происходит с точками и дефисами

При индексации содержимое файла делится по пробелам, табуляции и переводам строк. Затем у каждого фрагмента удаляется обычная пунктуация по левому и правому краю. Внутренние знаки остаются. Точки, дефис -, скобки и обычные кавычки по краям не являются частью индексного слова.

Фрагмент в документе Что попадёт в индекс Как вводить запрос
.СЛОВО. СЛОВО слово
.-СЛОВО-. СЛОВО слово
(СЛОВО), СЛОВО слово
СЛОВО-СЛОВО СЛОВО-СЛОВО слово-слово
СЛОВО.СЛОВО СЛОВО.СЛОВО слово.слово
СЛОВО,СЛОВО без пробела СЛОВО,СЛОВО Это один фрагмент; отдельное слово с ним не совпадает

Это обрезка краёв, а не удаление всей пунктуации и не разбиение по каждому дефису. Современные типографские тире и кавычки не следует считать гарантированно равными обычным ASCII-знакам в индексе OEM-866.

Важная особенность текущей реализации: сам запрос сервер делит на слова по пробельным разделителям, но не выполняет такую обрезку краёв. Клиент тоже её не выполняет. Поэтому документ с .СЛОВО. находится по запросу слово, а запрос .слово. не равнозначен слово и обычно не найдёт его. Для обычных слов убирайте внешние точки, скобки, дефисы и кавычки вручную.

Кавычки не включают поиск точной фразы, а * не означает произвольное окончание в текстовом режиме. Для демонстрации триммирования показывайте знаки в документе, вводя в запросе уже очищенное слово.

4. Поиск в таблицах AutoPad

  1. Включите SQL. Клиент сам выключит и заблокирует OEM-866 для этого режима.
  2. Выберите Вх. или Исх.: за один запрос выбирается один вид базы. Чтобы проверить оба, выполните два поиска и сохраните нужное до следующего.
  3. Выберите Поле: например Вх/исх №, Подписной №, Кр. содерж., Куда/откуда, Подп./исп., Тел. №, дату или имя приложения.
  4. Введите значение, укажите положительное Максимальное число ответов.
  5. Для начала оставьте Точное совпадение выключенным. При необходимости включите его и повторите запрос.
  6. Нажмите Поиск, проверьте статус и нужную карточку.

Без точного совпадения ищется фрагмент поля: значение поля должно содержать введённую строку. Это широкий поиск, но не исправление опечаток. Если ввести несколько слов, ищется эта строка целиком, с её пробелами и порядком; правило «все слова в любом месте» сюда не переносится.

С точным совпадением всё значение поля должно равняться запросу. Это не поиск одного точного слова внутри длинного поля. Лишние пробелы и знаки могут помешать. Код строит варианты запроса в верхнем и нижнем регистре; для полей с произвольным смешанным кириллическим регистром не обещается полноценное сравнение без учёта регистра.

Поле и запрос Без точного совпадения С точным совпадением
№: 123 Может найти 123, 1234, 9123 Только значение 123
Краткое содержание: связ Ищет этот фрагмент, например в «СВЯЗЬ» Всё поле должно равняться «СВЯЗ» либо «связ»
Исполнитель: ИВАНОВ Может найти «ИВАНОВ И.И.» Поле «ИВАНОВ И.И.» не равно «ИВАНОВ»
Краткое содержание: проверка связи Ищет эту последовательность внутри поля Всё поле должно равняться этой строке

В широком режиме действуют SQL-шаблоны: % означает любую последовательность символов, _ — один символ. Они не обязательно будут искаться буквально. Для обычного поиска вводите обычный фрагмент; для точного имени файла с подчёркиванием используйте точное совпадение, если известно полное значение.

5. Все месяцы, годы и лимиты

Месяц в интерфейсе выбирать не требуется: сервер сам просматривает доступные базы выбранного вида за настроенный год. Используются помесячные 01–12, также поддерживается служебная база 13. Живой сервер текущего года учитывает оперативную ARCHIVE.db3, если она существует; замороженный работает по годовым помесячным базам.

Поиск идёт по доступным на сервере источникам. Отключённая база входящих или исходящих даёт пустой ответ. Один запрос может искать по нескольким годам: выберите группу, включающую службы этих лет. Клиент сам не перебирает весь каталог; он обращается к авторизованным участникам выбранной группы. Настройка «Все года»: Серверы и группы.

В SQL-режиме число из Максимальное число ответов ограничивает суммарную выборку всех баз одного сервера, а не каждого месяца. Исходное значение — 30. Сервер начинает с оперативной базы текущего года, затем просматривает месяцы в обратном порядке; внутри базы строки идут по убыванию учётного индекса. При достижении лимита более ранние базы могут остаться непросмотренными. Это не гарантия глобальной сортировки всех месяцев по дате.

В текстовом режиме лимит задаётся серверным max_response; поле SQL-лимита его не меняет. Из индекса отдаётся ограниченное число наиболее релевантных результатов. На нескольких серверах лимиты действуют независимо: два сервера с SQL-лимитом 30 могут вернуть до 60 строк. Увеличение лимита не исправляет неудачный запрос и не возвращает ответ неавторизованного сервера.

6. Шаблоны повторяющихся запросов

  1. Настройте удачный запрос: текст, SQL/текстовый режим, Вх./Исх., поле и точность.
  2. В группе Шаблоны нажмите Сохранить. Задайте понятную группу, например «По номерам», и название шаблона.
  3. Нажмите Показать/скрыть, выберите группу, затем шаблон.
  4. Один щелчок применяет параметры; двойной применяет их и запускает поиск.
  5. Перед запуском проверьте год, источники, лимит и OEM-866. При переключении режима через шаблон явно проверьте флажок SQL и его зависимые параметры.

В Templates.json сохраняются только текст, поле, тип Вх./Исх., SQL и точное совпадение. Группа серверов, лимит, OEM, папка сохранения и колонки в шаблон не входят. Повторное сохранение с теми же группой и именем заменяет параметры. Контекстное Удалить удаляет шаблон; удаление группы после подтверждения удаляет все её шаблоны.

7. Если ответ не тот, который ожидался

Проверьте режим и источник: полное содержимое документа или поле таблицы. Для текста проверьте окончания слов, внешнюю пунктуацию запроса, внутренние дефисы и режим all/any на сервере. Для AutoPad проверьте вид Вх./Исх., поле, точность и лимит. Затем проверьте год, статус всех серверов и локальные фильтры таблицы результатов.

Поле SQL в списке полей принимает специальное условие для опытного пользователя; для обычных уроков достаточно именованных полей. Пустой запрос в этом режиме превращается в условие 1=1 с лимитом и выдаёт ограниченную выборку, а не поиск всех документов без ограничений.
