1. Что именно сохраняется

Флажок Результат Что требуется
Приложение Файлы приложений отмеченных документов Приложения/архив на сервере и доступ к нему
tlg Исходные байты текстового файла Доступный текст документа на сервере
docx Документ Word из полученного текста с обработкой макросом Microsoft Word и sht.docm рядом с EXE

tlg и docx взаимоисключающие: включение одного снимает другой. Приложение можно сочетать с любым из них. Для получения обоих текстовых вариантов выполните два сохранения.

Флажок tlg означает сохранение исходного текста без форматирования Word. Расширение берётся из имени исходного файла; если расширения нет, добавляется .tlg. Поэтому результат не обязательно всегда заканчивается на .tlg. Сохранение карточки в отчёт — отдельное действие Экспорт отчета.

2. Сохранить один документ или пакет

  1. Выполните поиск и проверьте документ по номеру, типу и дате.
  2. Поставьте галочки слева у нужных строк. Щелчок по строке для просмотра её текста ещё не выбирает её для сохранения. Пробел в таблице переключает отметку текущей строки.
  3. В группе Сохранение включите нужные флажки.
  4. В группе Директория укажите существующую доступную папку. Если поле пустое, после нажатия кнопки откроется выбор папки. Двойной щелчок по полю очищает его.
  5. Для нескольких строк при желании откройте меню кнопки Сохранить → Сделать отдельную папку.
  6. Нажмите Сохранить или Ctrl+S.
  7. Дождитесь окончания прогресса. Прочитайте журнал в области текста и проверьте созданные файлы.

Без отмеченных строк будет Ничего не выбрано!. Без флажков содержимого — Не выбрано что сохранять!. Несуществующая папка не принимается; выберите или создайте её заранее.

Отдельная подпапка создаётся только при числе отмеченных строк больше одного. Её имя берётся из текущего запроса; запрещённые для Windows символы заменяются дефисами. Это одна папка для выборки, а не отдельная папка для каждого документа. Проверьте конечный путь и журнал, особенно если строка запроса пустая или не подходит для имени папки.

Пакет получает текст сначала, затем входящие приложения, затем архивы исходящих. Для каждой строки используется её собственный сервер-источник. Скачивание не переносит и не удаляет серверные файлы.

3. Входящие приложения

Для входящего документа сервер объявляет отдельные файлы. Клиент получает список и проверяет, что нужное приложение в нём есть и доступно, после чего скачивает файл.

Для сохранения всех приложений отмеченной карточки используйте общий флажок Приложение. Имена берутся из сведений о приложениях карточки и проверяются по серверному списку. Если карточка сообщает нулевое число приложений, она пропускается для этой части; выбранный текст всё равно может сохраняться.

Чтобы получить одно приложение:

  1. Раскройте строку результата → Приложения:.
  2. Найдите имя со значением Доступен = Да.
  3. Нажмите кнопку в колонке доступности.
  4. Укажите папку и имя файла, подтвердите замену существующего файла, если диалог её предлагает.
  5. Дождитесь сообщения о сохранении и проверьте файл.

4. Исходящие приложения: ZIP и порядок извлечения

Для исходящего документа клиент не ищет отдельные приложения по произвольным путям. Сервер должен объявить архив <номер>.zip для выбранной телеграммы. Клиент скачивает его во временную папку и извлекает приложения на вашем ПК.

Оригинальные имена берутся из поля PrilName карточки, разделённого точками с запятой. Положение имени в списке определяет запись ZIP. Нулевая запись содержит тело телеграммы, приложения начинаются с первой.

Положение Пример имени в карточке Запись внутри ZIP
0 Тело документа MESSAGE/aps/make_msg/tmpvl000.srg — не приложение
1 схема.pdf MESSAGE/aps/make_msg/tmpvl001.srg
2 расчёт.xlsx MESSAGE/aps/make_msg/tmpvl002.srg
10 Десятое имя MESSAGE/aps/make_msg/tmpvl0010.srg

Последний пример важен: это приписывание номера после tmpvl00, а не форматирование номера до трёх цифр. Пользователю не требуется переименовывать внутренние .srg: клиент сохраняет их под именами из карточки.

При пакетном сохранении один архив скачивается на сочетание сервер + номер исходящего документа и из него извлекаются перечисленные приложения. При получении одного приложения через панель деталей клиент тоже скачивает ZIP целиком, затем извлекает только нужную запись. Остальные файлы из ZIP не публикуются как приложения.

Что означает «Доступен = Да» у исходящих: сервер подтвердил наличие ZIP. Содержимое каждой записи ещё не проверено; размер отдельного приложения в списке показывается как —. Повреждённый архив, отсутствующая запись или несогласованный порядок имён обнаруживаются уже при скачивании/извлечении.

Если обязательная запись отсутствует, это ошибка, а не успешное пустое приложение. Журнал укажет, сколько приложений распаковано и какая запись не найдена. Уже извлечённые файлы остаются. Соответствие содержимого и названия основано на порядке в карточке: если он ошибочен, клиент не может определить правильные имена по смыслу файлов. Передавайте такую карточку и ZIP специалисту, не переставляйте имена для исправления вручную.

Временные папки ZIP при штатном выходе из операции удаляются. В конечной папке лежат извлечённые приложения, а не автоматически сохранённый исходный ZIP. Пустые и недопустимые имена приложений пропускаются; общее наличие архива ещё не означает полноту пакета. Если карточка не указывает приложения, один лишь ZIP не заставит общий флажок скачать их.

5. Имена файлов и повторное сохранение

При пакетном сохранении существующий файл не должен молча заменяться: клиент подбирает свободное имя вида (1) имя.ext, (2) имя.ext. Это относится к тексту, DOCX и извлечённым приложениям. При большом числе совпадений подбор может завершиться ошибкой; используйте новую папку.

Одинаковые имена из разных документов не считаются одинаковым содержимым, даже если размеры совпали. При повторе после частичной ошибки уже полученные файлы могут сохраниться ещё раз под новыми именами. Для понятного комплекта лучше использовать отдельную чистую папку и проверять журнал.

Диалог получения одного приложения позволяет указать точное имя и подтверждает замену существующего файла. После подтверждения новый файл публикуется по выбранному пути. Это отличается от автоматического подбора имени в пакете.

6. Как создаётся DOCX

  1. Проверьте, что установлен Microsoft Word и рядом с EXE есть sht.docm из комплекта.
  2. Сначала попробуйте один небольшой документ: отметьте строку, включите docx, выберите папку и нажмите Сохранить.
  3. Клиент получает текст, преобразует его из OEM-866, приводит к верхнему регистру и передаёт Word.
  4. Word открывает sht.docm, помещает туда текст, выполняет макрос Обработка_ШТ_2022, затем сохраняет .docx.
  5. Откройте результат и проверьте абзацы, переносы, реквизиты и внешний вид. Только после этого переходите к большому пакету.

Макрос пытается оформить неформатированный текст телеграммы. Это преобразование текста, а не восстановление исходного оформления, скана или Word-приложения. Не обещается точная копия первоначальной вёрстки. DOCX не включает приложения автоматически: их сохраняет отдельный флажок.

Если Word блокирует макрос поставляемого шаблона, согласуйте доверие к этому файлу по правилам вашей организации. При ошибке или зависании запись в журнале показывает, какой документ пропущен. На холодный запуск Word отведено до 60 секунд; на макрос и сохранение после запуска — 15 секунд. Сбой одного документа не означает успешность всего пакета: следующие могут обрабатываться отдельно.

7. Отмена, ошибки и проверка результата

Отмена прекращает дальнейшую обработку пакета. Обычное сетевое получение текущего файла может завершиться прежде, чем отмена будет замечена; DOCX также получает сигнал отмены. Дождитесь возвращения кнопок в рабочее состояние. Закрытие клиента во время пакетного сохранения блокируется.

Прогресс учитывает задания: текст, отдельное входящее приложение или архив исходящих. Один шаг архива может дать несколько файлов. Завершённая шкала означает окончание обработки, а не отсутствие ошибок. Просмотрите сообщения об отсутствующих файлах, распаковке и DOCX.

После операции проверьте:

  • папку назначения и ожидаемые имена;
  • наличие всех нужных приложений, а не только текстового файла;
  • возможность открыть полученные файлы;
  • журнал частичных ошибок и число успешно обработанных заданий.

Ошибка сети, отсутствие архива, отказ сервера и ошибка Word требуют разных действий. Вначале повторите получение одного проблемного документа. Для отсутствующего ZIP/записи передайте специалисту номер, год, сервер и сообщение. Строки с удалённым документом пакетное сохранение пропускает.
