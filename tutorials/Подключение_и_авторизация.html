Сверено с клиентом 4.3.66 и сервером 0.1.91. Все темы: Все руководства.

1. Что именно соединяется

Каждая поисковая служба принимает TCP-соединения на своём порту и обслуживает настроенный на сервере год. Клиент выбирает из своего каталога все включённые подключения выбранной группы. Например, на одном компьютере служба 2025 года может слушать порт 15005, а служба 2026 года — 15006.

Верхний список Сервер / группа выбирает подключения. Имя группы может быть годом или произвольным названием и не меняет год работающей службы. Фактический год отдельно указывается в server_ports.server_year. Номер порта берите из фактической установки, а не вычисляйте только по году.

2. Местный вход и серверное разрешение

Способ Как используется Что проверяет сервер
Токен ПК Привязан к конкретному компьютеру; хранится в профиле текущего пользователя Windows Подпись, сведения о клиенте и устройстве, наличие разрешения
Токен USB Привязан к аппаратному серийному номеру флешки; носитель должен быть подключён Подпись, сведения о клиенте и устройстве, наличие разрешения
admin984.bin Местный admin, файл рядом с запущенным EXE; входит в комплект Текущее соединение должно прийти строго с 127.0.0.1

Для локальной установки на том же ПК используйте адрес 127.0.0.1. Имя localhost может разрешиться в IPv6, который не подходит для текущего режима местного admin. При удалённом подключении нужен подписанный токен; зелёное имя admin на клиенте не даёт сетевого доступа.

Местный вход показывает имя и делает доступной кнопку подключения. Только после проверки сервером появляется право выполнять запросы. Сервер проверяет каждое подключение отдельно: один токен может работать на одном сервере и быть отклонён на другом.

Без ручного выбора клиент предпочитает подходящий USB-токен, затем токен ПК, затем admin. Выбранный вручную доступный токен имеет приоритет. Если нужное имя присутствует, выберите именно его перед подключением. При смене личности прежние соединения и результаты могут очищаться.

3. Как импортировать готовый токен

  1. В верхнем списке авторизации выберите + Импортировать подписанный токен....
  2. Укажите Токен этого компьютера или Токен USB-флешки по привязке токена. Файл токена ПК, принесённый на флешке, остаётся токеном ПК.
  3. Выберите выданный searchclient-auth-token.json.
  4. Для ПК клиент проверит привязку и скопирует файл в %LOCALAPPDATA%\SearchEngine\. Для USB выберите файл непосредственно на подключённой подходящей флешке: клиент принимает его путь на носителе.
  5. Выберите появившееся имя и нажмите Подключение.

Клиент импортирует уже подписанный токен. Разрешение на удалённом сервере этот импорт не создаёт. Если организация использует мастер Setup-Access.bat, первоначальную настройку общего доступа выполняют по серверному tutorials\Общий_доступ_к_серверам.html; файл ответа access-answer.json устанавливают тем мастером, а не как токен клиента. Выдача токена другого ПК описана в серверном tutorials\Токен_удалённого_ПК.html.

Токен ПК ищется в профиле текущего пользователя, а не рядом с EXE и не в %ProgramData%. Перенос на другой ПК требует токена для нового компьютера. При отключении USB клиент пересматривает доступные личности: может переключиться на оставшийся токен ПК/admin либо снять местную авторизацию. Проверьте имя и подключитесь заново.

4. Настройка одного сервера

Если организация выдала готовую Settings.db3, обычно достаточно выбрать группу и подключиться. Для пустой конфигурации:

  1. Откройте Настройки → servers.
  2. У записи default заполните host фактическим IP/DNS. Для локального admin укажите 127.0.0.1.
  3. Откройте server_ports. Укажите тот же server_id, имя группы в god, фактический порт в port, год службы в server_year, enabled = 1.
  4. Завершите редактирование строки переходом на другую строку. Вернитесь на Поиск: клиент перечитает настройки и отключит прежние соединения.
  5. Выберите группу, нажмите Подключение, проверьте статус авторизации.

В пустом комплекте автоматически создаются default, адрес localhost и текущий системный год с первым кандидатом порта 15000 + последняя цифра года. Установщик сервера мог выбрать другой свободный порт. Другие группы и службы добавляйте явно; смена календарного года не создаёт новую строку в уже настроенном каталоге.

В текущем окне поле ручного ввода IP скрыто: сверху показывается список адресов и портов. Адреса меняйте через Настройки, в том числе для единственного сервера. SERVER_IP.INI служит лишь начальным источником адреса при пустом каталоге.

5. Настройка нескольких серверов и смысл группировки

Одинаковое значение server_ports.god объединяет источники в группу поиска. server_id связывает адрес и порт; для нескольких служб на разных портах одного компьютера в одной группе создайте отдельные идентификаторы. Разные годы могут входить в одну группу. Пример: Серверы и группы.

Таблица servers:

server_id display_name host enabled sort_order
main Основной 192.0.2.10 1 0
second Дополнительный 192.0.2.20 1 10

Таблица server_ports:

server_id god — группа port server_year enabled
main 2026 15006 2026 1
second 2026 16006 2026 1
main 2025 15005 2025 1

Адреса и порты здесь учебные. Подставьте свои. При выборе группы «2026» запросы пойдут на оба сервера; при выборе группы «2025» — только на main.

  1. Создайте уникальные server_id в servers, задайте адреса, понятные названия, enabled = 1 и различный sort_order.
  2. Для каждой группы добавьте включённый порт с соответствующим server_id; отдельно заполните server_year либо оставьте неизвестный год пустым.
  3. Вернитесь на Поиск, выберите группу и проверьте список host:port наверху.
  4. Подключитесь и проверьте K/N: настройки ещё не означают, что все серверы приняли токен.

Сервер участвует, только если включены и его строка в servers, и строка подключения данной группы. Основным становится первый по sort_order, затем по имени и идентификатору. Для понятного выбора задавайте разные порядковые числа. Основной используется для загрузки файлов, разноски и пользовательского пакета. Обновление! при нескольких источниках предлагает выбор сервера. Сохранение базы для описей всегда предлагает источник и год файла: Сохранение описи.

В текущем подписанном режиме сначала проверяется соединение с основным сервером. Если он недоступен, первоначальное подключение может прекратиться ещё до проверки остальных. Проверьте основной либо временно назначьте доступный сервер первым. Не настраивайте две записи одного и того же подключения: повторные результаты клиент автоматически не удаляет.

Группы шаблонов группируют запросы. Разрешения клиентов проверяются на сервере отдельно. Они не переключают список поисковых серверов. Набор источников выбирает список Сервер / группа; участие определяется обоими флагами enabled. Последняя доступная группа запоминается, затем используется settings.default_server_group. Если групп несколько и подходящей настройки нет, выберите группу вручную.

6. Что происходит при поиске и скачивании

Запрос выполняется параллельно на авторизованных серверах выбранной группы. Успешные ответы объединяются. При частичном отказе таблица остаётся доступной, но охватывает не все источники; прочитайте предупреждение. Лимит применяется отдельно на каждом сервере, дубликаты между ними не удаляются, релевантность между серверами не пересчитывается.

Каждая строка помнит сервер-источник. Текст, маршрут, подтверждения и приложения для неё клиент получает именно оттуда, в том числе при пакетном сохранении. Одинаковый номер документа на двух серверах не означает один и тот же документ.

При смене группы клиент переподключается и повторяет серверную авторизацию. Отключение разрывает соединения; зелёное местное имя может остаться. После изменения настроек или токена проверьте группу и нажмите Подключение.

7. Если подключиться не получилось

Симптом Что проверить
Нет местной авторизации Выбранный токен, его привязку к ПК/флешке и наличие носителя; для локального режима — admin984.bin рядом с фактическим EXE
Для группы нет серверов Связь server_id, god, обе галочки enabled
Ошибка соединения Адрес и фактический порт, запущенную службу, сеть; основной сервер при подписанном входе
Местное имя есть, сервер отказал Разрешение клиента и открытый ключ на этом сервере; для admin — соединение с 127.0.0.1
Авторизовано K из N Какие источники отказали; устраните причину, затем повторите подключение

Если предложены подробности серверной ошибки, откройте их и передайте специалисту код, сообщение, группу, год службы и имя проблемного сервера. Пароль в этом процессе не вводится; нужный токен выдаёт ответственный за доступ.

После перевыпуска ключа издателя

Если администратор сменил ключ проверки сервера, прежний токен будет отклонён при новой авторизации, даже при сохранённом разрешении устройства. Получите новый токен с прежней привязкой к ПК или флешке, согласуйте переключение серверов и подключитесь заново. Отключённая запись автоматически не включается; переустановка клиента не нужна.
