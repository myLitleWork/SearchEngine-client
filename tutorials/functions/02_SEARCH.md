# Поиск телеграмм

### Назначение

Основная функция программы: найти входящие или исходящие телеграммы на подключённых серверах по тексту запроса или по полям и показать результаты в таблице.

### Когда её использовать

- нужно найти документ по номеру, содержанию, адресату, исполнителю, дате и т.п.;
- нужно собрать выборку с одного или нескольких серверов за выбранный год;
- нужно подготовить список строк для сохранения или отчёта.

### Где она находится

Вкладка **Поиск**:

- поле запроса;
- кнопка **Поиск**;
- флажки **SQL**, **Точное совпадение**, **OEM-866**;
- группа **Тип** (Вх./Исх.);
- **Поле** и **Максимальное число ответов**;
- таблица результатов;
- горячая клавиша `Ctrl+F`.

### Что нужно подготовить

1. Успешную авторизацию и подключение.
2. Правильный год.
3. Текст запроса или параметры SQL.
4. Понимание, на каких серверах может лежать документ (при многосерверном режиме).

### Пошаговое использование

#### Обычный (полнотекстовый) поиск

1. Убедитесь, что флажок **SQL** выключен.
2. При необходимости оставьте **OEM-866** включённым.
3. Введите запрос в поле (подсказка: **Введите запрос**).
4. Нажмите **Поиск** или `Ctrl+F`.
5. Дождитесь заполнения таблицы и обновления статуса.

#### Поиск по полю (SQL)

1. Включите **SQL** (или нажмите `Alt+F1` / `Alt+F2` для быстрого режима Вх./Исх.).
2. Выберите **Вх.** или **Исх.**
3. Выберите **Поле** (или `Alt+F3` для раскрытия списка).
4. При необходимости включите **Точное совпадение**.
5. Задайте **Максимальное число ответов**.
6. Введите значение в поле запроса.
7. Нажмите **Поиск**.

#### Произвольное SQL-условие

1. Включите **SQL**.
2. Выберите поле **SQL**.
3. Введите условие в строку запроса (программа добавит `order by … limit …`).
4. Если строка пуста, программа может подставить `1=1` автоматически.

### Параметры функции

| Параметр | Назначение | Что меняется |
|---|---|---|
| Текст запроса | Что искать | Тело запроса к серверу |
| SQL | Режим поиска | Команда и набор параметров |
| Тип Вх./Исх. | Какая база | Серверная команда Вх. или Исх. |
| Поле | Атрибут SQL-поиска | Шаблон условия |
| Точное совпадение | Жёсткость условия | Вид SQL |
| Макс. число ответов | Лимит | На **каждый** сервер |
| OEM-866 | Перекодировка | Только вне SQL |
| Год / список серверов | Где искать | Набор endpoint’ов |

### Пример

Нужен входящий № `12345` за 2025 год:

1. Год = `2025`.
2. `Alt+F1` (SQL + Вх. + поле номера).
3. Ввести `12345`.
4. При необходимости включить **Точное совпадение**.
5. Нажать **Поиск**.
6. В таблице появляется строка(и); статус показывает число серверов и результатов.

### Что происходит после запуска

1. Очищаются предыдущие локальные результаты.
2. Запрос параллельно отправляется на все включённые серверы выбранного года.
3. Ответы объединяются в один список **без удаления дубликатов**.
4. Каждой строке назначается `source_server_id` (сервер-источник).
5. Данные записываются в локальную таблицу `res` и показываются в сетке.
6. При одном результате строка может быть выбрана автоматически с попыткой загрузки текста.
7. Если часть серверов не ответила — показывается предупреждение, но успешные результаты остаются.
8. Если часть строк не удалось записать локально — таблица показывает сохранённые строки,
   статус помечает частичность, а в панели текста (`rchEdt`) остаётся расшифровка:
   какая строка, какое поле/вставка и текст ошибки. При автозагрузке единственной
   телеграммы отчёт об ошибках не затирается: текст добавляется под блоком диагностики.

### Как понять, что операция завершилась успешно

- Статус: `Поиск завершён: серверов N, результатов M` — `M` это число **фактически
  сохранённых** строк, а не только размер ответа сервера.
- Частичная запись: `Поиск завершён частично: сохранено X из Y` (и/или частичный
  ответ серверов); детали — в панели текста.
- Таблица заполнена сохранёнными строками.
- Кнопка поиска снова доступна.
- При выборе строки справа появляется текст (если файл не удалён); при наличии
  отчёта о сохранении он остаётся над текстом телеграммы.
- Релевантность (`rel`) сохраняется как вещественное число.

### Возможные проблемы

| Симптом | Что проверить |
|---|---|
| Ничего не происходит при пустом запросе | Вне SQL пустой запрос игнорируется |
| `Ни один сервер не ответил успешно` | Сеть/серверы/год |
| `Идёт обновление базы` | Повторить позже |
| Частичный ответ серверов | Смотреть список недоступных серверов |
| Частичная запись в локальную таблицу | Панель текста: номер строки, поле/вставка, текст ошибки; статус `сохранено X из Y` |
| Слишком много строк | Уменьшить лимит; помнить про умножение на число серверов |
| Строка серая «удалён» | Файла нет, только след индекса |

### Важные замечания и ограничения

- Локальные результаты временные и будут очищены при следующем поиске/подключении/запуске.
- Лимит не общий, а **посерверный**.
- Релевантность между серверами не пересчитывается заново.
- История запросов в выпадающем списке — до 9 позиций и только в текущем сеансе.
- Во время поиска кнопка может быть временно недоступна; параллельно идёт фоновая задача.
- Закрытие окна во время поиска дожидается фоновой задачи; callback не трогает UI после начала уничтожения формы.
