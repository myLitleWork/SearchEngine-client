# Подключение и авторизация

### Назначение

Функция обеспечивает вход пользователя в программу и установку сетевого соединения с поисковыми серверами выбранного года. Без успешной авторизации и подключения поиск, просмотр текста и большинство операций недоступны.

### Когда её использовать

- при первом запуске смены;
- после смены года;
- после обрыва связи;
- после размещения выданного файла-заглушки;
- перед поиском, если статус показывает отключение или ошибку.

### Где она находится

Верхняя панель главного окна:

- надпись авторизации;
- поле IP;
- список годов;
- кнопки **Подключение**, **Отключение**, **Обновление!**

Авторизация дополнительно выполняется автоматически по таймерам (без отдельной кнопки «Войти»).

### Что нужно подготовить

1. Входящий в релиз `admin984.bin` рядом с EXE.
2. Настроенные год и серверы (`servers` / `server_ports`).
3. Доступность сервера по сети.

### Пошаговое использование

#### Автоматический вход

1. Запустите программу.
2. Убедитесь, что `admin984.bin` лежит в том же каталоге, что и EXE.
3. Подождите 1–2 секунды.
4. Убедитесь, что появилось `Авторизация : &lt;имя&gt;` (зелёный цвет).
5. Проверьте статус подключения в строке **Статус:**.

#### Ручное подключение

1. Проверьте/введите адрес в поле IP (актуально, если включён один сервер).
2. Выберите год.
3. Нажмите **Подключение**.
4. Дождитесь статуса вида `Статус: настроено серверов N, основной подключён, &lt;год&gt; год` (формулировка зависит от результата).
5. Убедитесь, что кнопка **Поиск** активна.

#### Отключение

1. Нажмите **Отключение**.
2. Статус станет `Статус: отключено от сервера`.
3. Основные рабочие элементы будут отключены.

#### Смена года

1. Выберите другой год в списке.
2. При активной авторизации программа сама выполнит переподключение.

### Параметры функции

| Параметр | Назначение | Рекомендации |
|---|---|---|
| IP / host | Адрес основного/единственного сервера | Значение от администратора |
| Год | Выбор портов и баз | Год нужного документа |
| `admin984.bin` | Временная локальная заглушка пользователя `admin` | Обязательный файл релиза |
| Каталог серверов | Многосерверный режим | См. настройки `servers` |

Подробнее: [../SETTINGS_REFERENCE.md](../SETTINGS_REFERENCE.md).

### Пример

1. Проверяете, что пакетный `admin984.bin` находится рядом с EXE.
2. Через секунду видите `Авторизация : admin`.
3. В списке годов выбираете `2025`.
4. Нажимаете **Подключение**.
5. Статус показывает успешную настройку серверов и подключение основного.
6. Переходите к поиску.

### Что происходит после запуска

1. Проверяется/обновляется host сервера `default` (если сервер один).
2. Из базы настроек собираются endpoint’ы выбранного года.
3. Выполняется TCP-подключение к основному серверу.
4. Выполняется регистрация пользователя на сервере (`USER_REGISTRY`, ожидается ответ `OK`).
5. Остальные серверы при необходимости подключаются позже, во время поиска/запросов к владельцу строки.
6. Локальная таблица результатов очищается.

### Как понять, что операция завершилась успешно

- Есть `Авторизация : …`.
- Нет окна с ошибкой подключения/регистрации.
- Статус не содержит `ошибка` / `нет подключения` / `отключено`.
- Доступны **Поиск** и связанные кнопки.

### Возможные проблемы

| Проблема | Что сделать |
|---|---|
| Нет авторизации | Проверить имя и расположение `admin984.bin` рядом с фактически запущенным EXE |
| `Ошибка подключения` | Проверить IP, порт года, сеть |
| `Ошибка регистрации` | Проверить учётную запись на сервере |
| `Не выбран год` / нет серверов | Заполнить `server_ports` |
| Идёт сохранение файлов | Дождаться окончания, затем подключаться |

См. также [../TROUBLESHOOTING.md](../TROUBLESHOOTING.md).

### Важные замечания и ограничения

- Пароль в окне не вводится; текущая временная схема использует только
  `admin984.bin`.
- Signed-token авторизация `token-HS.bin` временно отключена, но её код сохранён
  разработчиками для возможного возврата. RSA-ключи автоматически не создаются.
- Для `admin` автоматический выход при удалении файла сейчас не выполняется;
  после удаления заглушки перезапустите клиент.
- Административные операции всегда идут на основной сервер (первый по `sort_order`).
- Во время пакетного сохранения подключение блокируется сообщением о необходимости дождаться завершения.
- Закрытие окна во время входа/выхода или сохранения описи дожидается фонового
  callback; UI после уничтожения формы не трогается.
- Клиент не выполняет групповое разграничение прав. Авторизацию каждой
  операции и доступ к данным обязан проверять сервер.
