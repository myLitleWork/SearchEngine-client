# Подключение и авторизация

## Общий доступ и импорт токена ПК

Для первоначальной настройки двух серверов используйте **Setup-Access.bat**
из полного серверного пакета. Этот мастер подготавливает заявку, получает подпись
главного ПК и устанавливает ответ: открытый ключ на серверы, разрешения клиентов
и местный токен этого ПК. У каждого ПК свой токен; закрытый ключ не переносится.
Подробная инструкция находится в серверном пакете: tutorials/ACCESS_SETUP.html.

В списке авторизации пункт **+ Импортировать подписанный токен...** предназначен
для отдельного готового токена. В окне импорта выбирайте по его привязке:

- **Токен этого компьютера** — даже если файл принесли на обычной флешке;
- **Токен USB-флешки** — если подписанный токен привязан к самой флешке.

Этот импорт сам по себе не добавляет разрешение на удалённом сервере.
Для файла ответа access-answer.json используется пункт 4 мастера Setup-Access.bat.
После настройки выберите токен ПК и нажмите **Подключение**: проверьте авторизацию
на каждом сервере нужного года. Зелёное имя подтверждает только местный вход.

### Назначение

Функция обеспечивает **локальный** вход (флешка / `admin984.bin`) и **серверную**
авторизацию выбранного года. Локальная зелёная надпись `Авторизация : …` сама по
себе не открывает поиск: рабочие операции доступны только после успешного
server-auth хотя бы на одном сервере.

### Когда её использовать

- при первом запуске смены;
- после смены года;
- после обрыва связи;
- после размещения `admin984.bin` или вставки USB-токена;
- перед поиском, если статус показывает отключение, ошибку или «нет серверной авторизации».

### Где она находится

Верхняя панель главного окна:

- список локальных токенов (USB / ПК / admin) и пункт импорта;
- надпись авторизации (локальный вход);
- поле IP;
- список годов;
- кнопки **Подключение**, **Отключение**, **Обновление!**

Локальная авторизация выполняется автоматически (WMI/флешка или `admin984.bin`);
нужный токен можно выбрать вручную в списке. Серверная — при запуске (если
локальный вход уже есть), по кнопке **Подключение** или при смене года. Если
клиент запущен без какой-либо авторизации, первая принятая USB-флешка также
запускает одну автоматическую попытку подключения. При готовности носителя с
задержкой клиент повторяет обнаружение до 15 секунд в фоне; извлечение флешки
или закрытие клиента отменяет ожидание. Ошибка соединения не запускает
бесконечные повторные подключения: используйте **Подключение**. На время
сетевого ожидания показывается окно со списком серверов подключения.

ПК-токен ищется только в профиле текущего пользователя Windows. Общий файл в
`%ProgramData%` и файл рядом с EXE больше не используются для ПК-входа.
При обновлении перенесите прежний токен в `%LOCALAPPDATA%\SearchEngine\`
под нужной учётной записью; подпись и повторная регистрация не требуются.

### Что нужно подготовить

1. Либо USB-токен `searchclient-auth-token.json` на флешке, либо PC-токен
   (`%LOCALAPPDATA%\SearchEngine\searchclient-auth-token.json`),
   либо `admin984.bin` рядом с EXE (приоритет: USB, затем PC, затем admin).
2. Настроенные год и серверы (`servers` / `server_ports`).
3. Доступность серверов по сети.
4. В portable/run layout — `config/server-error-messages.json` рядом с EXE
   (входит в релизный пакет), чтобы коды вроде `AuthFailed` (33) показывались
   текстом из JSON, а не как «внутренняя ошибка».

### Пошаговое использование

#### Автоматический локальный вход

1. Запустите программу.
2. Вставьте выданную флешку **или** убедитесь, что `admin984.bin` лежит рядом с EXE.
3. Подождите 1–2 секунды.
4. Убедитесь, что появилось `Авторизация : &lt;имя&gt;` (зелёный цвет).
5. Кнопка **Подключение** активна; **Поиск** ещё нет — нужен server-auth.

#### Выбор и импорт токена

1. Если в списке несколько имён, выберите нужное (USB, ПК или admin).
2. Для готового подписанного файла выберите **+ Импортировать подписанный токен...**.
3. Укажите, это токен **этого компьютера** или **USB-флешки**, затем укажите файл.
4. После смены токена нажмите **Подключение**, если автоподключение уже прошло.

#### Ручное подключение (server-auth)

1. Проверьте/введите адрес в поле IP (актуально, если включён один сервер).
2. Выберите год.
3. Нажмите **Подключение**.
4. Дождитесь статуса:
   - **admin:** `Статус: настроено серверов N, основной подключён, &lt;год&gt; год`;
   - **flash:** `Статус: авторизовано серверов K/N, &lt;год&gt; год`.
5. Убедитесь, что кнопка **Поиск** активна (нужен K ≥ 1).

#### Отключение

1. Нажмите **Отключение**.
2. Статус станет `Статус: отключено от сервера`.
3. Локальная надпись может остаться зелёной (флешка на месте), но поиск и
   загрузка выключатся до нового **Подключения**.

#### Смена года

1. Выберите другой год в списке.
2. При активной локальной авторизации программа сама выполнит переподключение
   и повторный server-auth по правилам admin/flash.

### Параметры функции

| Параметр | Назначение | Рекомендации |
|---|---|---|
| IP / host | Адрес основного/единственного сервера | Значение от администратора |
| Год | Выбор портов и баз | Год нужного документа |
| USB-токен | Локальный USB-вход + `AUTHENTICATE_V1` | Приоритет над PC и admin |
| PC-токен | Локальный computer-вход + `AUTHENTICATE_V1` | `%LOCALAPPDATA%\SearchEngine\` |
| `admin984.bin` | Локальный admin + legacy `USER_REGISTRY` | Без `AUTHENTICATE_V1` |
| Каталог серверов | Многосерверный режим | См. настройки `servers` |

Подробнее: [../SETTINGS_REFERENCE.md](../SETTINGS_REFERENCE.md).

### Пример

**Admin**

1. Рядом с EXE есть `admin984.bin`, флешки нет.
2. Видите `Авторизация : admin`.
3. Нажимаете **Подключение** → статус «основной подключён».
4. Поиск работает; в трафике нет `AUTHENTICATE_V1`.

**USB**

1. Вставлена флешка с токеном; в auth DB сервера есть запись.
2. Видите `Авторизация : Иванов` (это ещё только локальный вход).
3. Нажимаете **Подключение** → `AUTHENTICATE_V1` с `device_type=usb` и `device_id` (hardware serial).
4. Статус `авторизовано серверов K/N`; поиск только по авторизованным.

**PC**

1. USB нет; есть валидный `searchclient-auth-token.json` в `%LOCALAPPDATA%\SearchEngine\`.
2. Видите `Авторизация : Иванов`.
3. **Подключение** шлёт `AUTHENTICATE_V1` с `device_type=computer` и SMBIOS UUID. `flash_serial` не используется.

### Что происходит после «Подключение»

1. Обновляется host сервера `default` (если сервер один).
2. Из базы настроек собираются endpoint’ы выбранного года.
3. TCP + согласование протокола с серверами.

Дальше пути **не смешиваются**:

| Локальный вход | Server-auth | Поведение |
|---|---|---|
| `admin984.bin` | `USER_REGISTRY` (legacy) | Как раньше: основной при Connect, остальные при поиске |
| USB-токен | `AUTHENTICATE_V1` на **каждый** enabled server | Без тихого `USER_REGISTRY`; провал V1 = сервер не авторизован |
| PC-токен | тот же `AUTHENTICATE_V1` | Если USB нет или USB-token не подходит текущему носителю |

4. UI поиска/загрузки включается только если есть хотя бы один server-authorized endpoint.
5. Локальная таблица результатов очищается.

### Многосерверная матрица (flash)

| Flash в auth DB | Поведение клиента |
|---|---|
| Есть на обоих | Connect OK, поиск по обоим |
| Есть только на A | Поиск по A; по B — ошибка/пропуск с текстом; UI частично работоспособен |
| Нет ни на одном | Connect fail, поиск выключен, статус не «подключён» |
| Admin `admin984.bin` | Без V1; `USER_REGISTRY`; поиск работает |

### Как понять, что операция завершилась успешно

- Есть `Авторизация : …` (локально).
- Нет окна с ошибкой подключения/AuthFailed.
- Статус не содержит `ошибка` / `нет подключения` / `отключено`.
- Для flash: `авторизовано серверов K/N` с K ≥ 1.
- Доступны **Поиск** и связанные кнопки.

### Возможные проблемы

| Проблема | Что сделать |
|---|---|
| Нет авторизации | Проверить флешку/токен или `admin984.bin` рядом с EXE |
| Зелёный `lblUser`, но поиск серый | Нажать **Подключение**; нужен server-auth |
| `AuthFailed` / код 33 | Клиента нет в auth DB сервера; текст должен быть из `server-error-messages.json` |
| `AuthRequired` / код 35 | Операция без server-auth; подключиться заново |
| `Ошибка подключения` | Проверить IP, порт года, сеть |
| `Ошибка регистрации` (admin) | Проверить учётную запись / ответ `USER_REGISTRY` |
| «внутренняя ошибка 33» | Рядом с EXE нет актуального `config/server-error-messages.json` |
| `Не выбран год` / нет серверов | Заполнить `server_ports` |
| Идёт сохранение файлов | Дождаться окончания, затем подключаться |

См. также [../TROUBLESHOOTING.md](../TROUBLESHOOTING.md).

### Важные замечания и ограничения

- Пароль в окне не вводится.
- Flash и admin **не смешивают** wire-пути: USB/PC → только `AUTHENTICATE_V1`,
  admin → только `USER_REGISTRY`.
- После `AuthFailed` локальный зелёный `lblUser` допустим, но Search/Load не
  обходят server-auth gate.
- Signed-token авторизация `token-HS.bin` временно отключена, но её код сохранён
  разработчиками для возможного возврата. RSA-ключи автоматически не создаются.
- Для admin выход при удалении `admin984.bin` выполняется таймером; для flash —
  при извлечении носителя (WMI) с safety-net таймером.
- Административные операции всегда идут на основной сервер (первый по `sort_order`).
- Во время пакетного сохранения подключение блокируется сообщением о необходимости дождаться завершения.
- Закрытие окна во время входа/выхода или сохранения описи дожидается фонового
  callback; UI после уничтожения формы не трогается.
- Клиент не выполняет групповое разграничение прав. Авторизацию каждой
  операции и доступ к данным обязан проверять сервер (`AuthRequired` и др.).
