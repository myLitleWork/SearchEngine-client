# Многосерверный поиск клиента

Клиент хранит список поисковых серверов в `Settings.db3`. При первом запуске
после обновления существующие `SERVER_IP.INI` и таблица `ports` автоматически
переносятся в записи сервера `default`; исходные настройки не удаляются.

## Таблицы конфигурации

`servers`:

- `server_id` — стабильный уникальный идентификатор;
- `display_name` — имя для статусов;
- `host` — DNS-имя или IP-адрес;
- `enabled` — `1`, если сервер участвует в поиске;
- `sort_order` — порядок серверов; первый сервер считается основным.

`server_ports`:

- `server_id` — ссылка на `servers.server_id`;
- `god` — год базы;
- `port` — TCP-порт этого года на сервере;
- `enabled` — `1`, если endpoint включён.

Таблицы доступны на существующей вкладке настроек клиента. Изменения списка
серверов применяются после выхода со вкладки настроек и следующего подключения
или смены года.

Пример логической конфигурации:

```text
servers
default | Основной   | 192.0.2.10 | 1 | 0
archive | Архивный   | 192.0.2.20 | 1 | 1

server_ports
default | 2025 | 9101 | 1
archive | 2025 | 9201 | 1
```

## Поведение

- поисковый запрос выполняется параллельно на всех включённых endpoint'ах
  выбранного года;
- заданный пользователем лимит применяется отдельно на каждом сервере;
- успешные ответы объединяются без dedup и без пересчёта релевантности;
- при частичном отказе успешные результаты показываются вместе с перечнем
  недоступных серверов;
- каждая строка сохраняет `source_server_id`; текст, путь, PDTV, вложения и
  пакетное скачивание направляются серверу-владельцу строки;
- административные операции выполняются только на основном сервере.

Debug-сборка поддерживает безопасную локальную проверку транспорта:

```powershell
Win32\Debug\SearchClient_asio.exe --multi-server-self-test
```

Код возврата `0` означает, что два локальных тестовых сервера независимо
прошли регистрацию и вернули корректные параллельные ответы.
