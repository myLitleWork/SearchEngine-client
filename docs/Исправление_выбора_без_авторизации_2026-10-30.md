## Причина сообщения на снимке

Обработчик `formMain.cpp:4895` (`cmbAuthUserChange`) различал admin и «всё остальное». Выбранный пункт Anonymous попадал в `applyResolvedDeviceIdentity` с пустой структурой; режим становился Computer при пустых идентификаторах.

`resolveLiveDeviceIdentity` также возвращал пустую identity нового пункта как заполненный optional. `btnConnectClick` считал этот optional токеном и выбирал ветку AUTHENTICATE_V1. Затем `tryConnect` обнаруживал пустые client_id/device_type/device_id и устанавливал LegacyUserRegistry. Вызов authenticateAllV1 встречал другой локальный режим.

Текст `AUTHENTICATE_V1 недоступен в режиме USER_REGISTRY` формирует сам клиент (`Net/MultiServerManager.h:126`) до отправки запроса авторизации серверу. У оператора поля identity заполнены, поэтому эта последовательность ошибок не возникала. Наличие/режим службы на пользовательской Windows 7 по одному снимку не установлен.

## Исправление

- `formMain.cpp:4905`: ручной выбор Anonymous вызывает `applyAnonymousAccess`, закрывает предыдущие соединения, очищает данные токена текущей сессии и задаёт AnonymousOnly.
- `formMain.cpp:4947`: явно выбранные Anonymous и Admin не выполняют поиск токенов при подключении/переподключении. Для ручного выбора identity возвращается только для USB или Computer.
- Установленные токены и файлы на флешке не удаляются. Числа команд, payload, capability и серверная проверка доступа не менялись.
- В руководство общего доступа добавлен переход от оператора; редакция всех24 HTML обновлена до4.3.78.
