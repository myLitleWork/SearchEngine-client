## Предмет и результат

Пользователь уточнил, что подсветка смещается в зависимости от ширины панели
текста и обработки переносов. Изменение оформления совпадений не является
основным предметом запроса.

Причина подтверждается устройством текущего алгоритма: `setColor` перебирает
`rchEdt->Lines`, а позицию следующей строки получает прибавлением её длины и
единицы. В RichEdit этот список содержит также строки, полученные переносом
по ширине окна. Мягкий перенос не добавляет символ в текст, поэтому такая
единица создаёт накопленное смещение.

| Проверенный факт | Доказательство | Результат |
|---|---|---|
| Позиции считаются вручную через длины строк и `+ 1` | `formMain.cpp:2802–2819` | Причина зависимости от переноса по ширине подтверждена статически |
| VCL получает строки через `EM_GETLINECOUNT` / `EM_GETLINE` и удаляет конечный CR | Установленный `Vcl.ComCtrls.pas:14754–14780` | Представление строк нельзя использовать для такого накопления позиций |
| Нативный поиск доступен через `TRichEdit::FindText` | `Vcl.ComCtrls.pas:16089–16110`; поиск вызывает `EM_FINDTEXT`, CRLF запроса преобразуется в CR | Можно получать позиции непосредственно в системе координат RichEdit |
| Выделяется только первое вхождение слова в строке | `formMain.cpp:2809–2815`, повторного поиска в строке нет | Дополнительное ограничение существующей реализации |
| Подсветка вызывается двумя путями | `formMain.cpp:1219–1241`, `2853–2863` | Оба используют `setColor`, исправление можно сосредоточить в общем месте |

## Находки и предлагаемое исправление

| ID | Проблема | Статус на 28.10.2026 |
|---|---|---|
| П01 | Виртуальные переносы учитываются как символы; подсветка смещается | Открыта; подтверждена статически |
| П02 | Повторные вхождения в одной строке пропускаются | Открыта; подтверждена статически |

Предлагается заменить обход `Lines` последовательным нативным поиском по
всему содержимому RichEdit. Использовать возвращённые компонентом позиции
для форматирования и следующего поиска; не вычислять смещения по CR/LF или
экранным строкам. При применении форматирования сохранять выделение и прокрутку.
Такой способ также позволит находить фрагмент, визуально разделённый переносом.

Оценка: небольшая локальная правка клиента, ориентировочно 2–4 часа со сборкой
и проверкой. Сервер, wire-протокол и базы для этого исправления менять не
требуется. Оценка относится к позициям буквальных совпадений; полное соответствие
произвольным SQL-условиям и серверной нормализации отдельно не исследовалось.
