# Состав релизного пакета SearchClient

Инженерная заметка о принятом составе portable-поставки. Пользовательские
руководства находятся в `tutorials/` и автоматически включаются в пакет.
Все руководства поставляются в HTML с русскими именами; начинать следует с
[tutorials/00_Все_руководства.html](../tutorials/00_Все_руководства.html).

## Принятое правило

`scripts/New-SearchClientPackage.ps1` собирает `app/` только по явному
allowlist. Наличие файла рядом с Release EXE больше не означает, что файл
попадёт в поставку. В пакет входит обезличенная начальная `Settings.db3` с
обязательными словарями полей и каноническая заглушка `admin984.bin` для
текущего временного режима авторизации. Настройки серверов задаются отдельно.

## Обязательный минимум по текущим данным

| Файл | Основание |
|---|---|
| `SearchClient_asio.exe` | Точка входа приложения |
| `sht.docm` | DOCX-конвертация вызывает макрос `Обработка_ШТ_2022` |
| `Settings.db3` | Начальная конфигурация со словарями `map*`; серверы и порты пусты |
| `admin984.bin` | Обязательная заглушка текущего временного режима авторизации `admin` |
| `tutorials/` | Пользовательская документация поставки |
| verifier, manifest, checksums | Проверка целостности релиза |

Каноническая копия Word-шаблона хранится в
`deployment/SearchClientPortable/app/sht.docm`. Проверенный SHA-256:
`85EB429F9BD08ACE7127729887520EE7EFC34AA348C290ACC6EE818F438B938F`.

Каноническая начальная база хранится в
`deployment/SearchClientPortable/app/Settings.db3`. В ней `map`/`map_ish`/
`map_vh` содержат соответственно 10/3/3 строки, а `ports`, `servers` и
`server_ports` пусты. Проверенный SHA-256:
`40A4D999B39B0FE4C18649DB71B7EC60222E8DDF28E2F059E24897B3032F0B13`.

## Отдельное организационное снабжение

Эти файлы могут быть нужны конкретному рабочему месту, но не должны входить в
общий пакет автоматически и не должны подхватываться из каталога сборки:

- `SERVER_IP.INI`: необязательный legacy fallback, без него используется
  `localhost`;
- `Templates.json`: необязательные пользовательские шаблоны, создаются клиентом.

`SearchRes.db3` является временной локальной базой результатов и создаётся
клиентом. Поставлять её не нужно.

## Не включать по текущим данным

- `token-HS.bin` и любые иные локальные учётные файлы, кроме канонической
  заглушки `admin984.bin`;
- `pubkey.pem`, `prikey.pem` и другие ключи: подписанные токены временно
  отключены, а RSA-ключи клиент больше не генерирует;
- `SearchRes.db3`, `Templates.json`, `SERVER_IP.INI` и рабочая `Settings.db3`
  из каталога сборки; в пакет попадает только обезличенный шаблон
  `deployment/SearchClientPortable/app/Settings.db3`;
- `myCrypto.dll`, `libcrypto-3.dll` и `libssl-3.dll`: текущий EXE не имеет
  обычных или delay-load импортов этих библиотек и не загружает их вручную.
  Legacy crypto-исходники пока сохранены, но import library отключена от
  линковки проекта;
- `OEM866.INI`, `hyphen_replacements.csv`, `misc_replacements.csv`: активных
  ссылок из runtime-кода не найдено;
- отдельный `.fr3`: текущий отчёт встроен в DFM;
- compiler intermediates, журналы SQLite и временные файлы;
- старые файлы групповой ACL и код резолюций: соответствующая клиентская
  функциональность удалена.

## Что ещё нужно подтвердить после рефакторинга

Это рабочая гипотеза состава, а не окончательная сертификация поставки.
Отдельной задачей нужен smoke-test чистого релизного каталога на машине без
остаточных файлов старой версии. В частности следует проверить:

1. все сценарии DOCX и отсутствие скрытых внешних зависимостей Word-макроса;
2. заполнение серверов и портов в поставляемой `Settings.db3`, подключение с
   входящим в пакет `admin984.bin`;
3. поиск, скачивание, загрузку и служебные операции с контролируемым сервером;
4. достаточно ли текущего набора пользовательских руководств;
5. запуск из чистого каталога без `myCrypto.dll`, `libcrypto-3.dll` и
   `libssl-3.dll`.

Подробный сценарий и входные данные: `docs/CONTROLLED_SMOKE_TEST.md`. До его
выполнения фактический минимальный набор файлов остаётся инженерной гипотезой.

Авторизацию и разграничение прав обязан проверять сервер. Эта обязанность
зафиксирована как требование, но фактическая серверная реализация в рамках
данной клиентской проверки не подтверждалась.

## Выполненная локальная проверка

08.08.2026 Debug-сборка после изменения авторизации завершилась без ошибок.
Проверка пути к заглушке выполнена копией EXE в каталоге с кириллицей длиной
144 символа: с `admin984.bin` код возврата 0, без него — ожидаемый код 51.
Причиной прежнего сбоя было преобразование Unicode-пути через ANSI, а не сама
глубина вложенности. 09.08.2026 Release-сборка также завершилась без ошибок;
обе сборки имеют только 8 прежних предупреждений `W6829`. Кандидат 4.3.0 прошёл
прежнюю проверку с четырьмя файлами `app/`. После добавления начальной
`Settings.db3` allowlist содержал пять файлов; после включения обязательного
`admin984.bin` содержит шесть файлов. Шаблон БД отдельно прошёл
`PRAGMA integrity_check`, проверку состава таблиц и SHA-256. Полная пересборка
нового кандидата отложена. Это не замена smoke-test с реальным сервером и
Microsoft Word.
