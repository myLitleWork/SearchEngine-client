## Реализация

В списке «Максимум ответов» добавлен пункт **Без лимита**. Только этот явный пункт обозначает отсутствие ограничения; ноль, отрицательное значение, переполнение и произвольный текст отклоняются. Для SQL AutoPad перестаёт добавляться LIMIT, при этом период, условие и сортировка сохраняются. Именованные поля и поле SQL поддерживают этот режим. Текстовый поиск по-прежнему использует серверный max_response.

У шаблонов v2 появился необязательный `unlimited_results`, по умолчанию false. При сохранении режима он записывается как true и восстанавливает пункт «Без лимита». Старые пять обязательных полей и старые JSON не меняются; `max_results=0` в старой записи не превращается автоматически в отсутствие лимита. У готовых шаблонов остаётся 300 на сервер; пользовательские параметры и файлы не мигрируются заново и не перезаписываются.

Проверенный серверный путь: `Telega::findBase` извлекает только явно указанный числовой LIMIT; без него обходит доступные базы и собирает все совпадения. `GetJsonTelegaCmd` затем формирует один JSON-массив. Поэтому обновлять сервер ради SQL без LIMIT не нужно. До получения и разбора ответа клиент не знает полного количества записей. Это статическое подтверждение текущего серверного checkout, не новый запуск рабочей службы.

Для поисковых запросов добавлена локальная координация `SearchRequestControl`: атомарные отмена, пауза, счётчики и завершение. Передача обслуживается асинхронными операциями сокета в его рабочем потоке с проверкой отмены каждые 100 мс. UI не закрывает чужой сокет и не ожидает session mutex. Прочие запросы сохраняют прежний idle timeout 10 секунд; поиск использует мягкий контроль ожидания, поэтому «Продолжить» действительно позволяет дождаться ответа позже 10 секунд. При отмене незаконченной транзакции сокет закрывается, запоздавший ответ не смешивается со следующим запросом. Автоматический повтор отменённого поиска запрещён; при закрытой сессии доступно «Подключение».

Через 20 секунд поиска/получения/подготовки показывается вопрос с тремя действиями:

1. «Продолжить ждать» — новый интервал 20 секунд.
2. «Отменить и поставить лимит 1000» — отмена и настройка следующего запроса, без автоматического запуска.
3. «Отменить поиск» — отмена без изменения лимита; закрытие диалога имеет тот же смысл.

При распознавании 100 000 записей обработка останавливается до отдельного решения. Показывается фактическое число распознанных записей по всем серверам, а не предположение о количестве в ещё не полученном ответе. Пока вопрос открыт, дальнейшая обработка приостановлена. Потоковый callback преобразует и удаляет каждый завершённый JSON-объект, не сохраняя второй полный DOM результата; отмена проверяется и при разборе.

Запись результатов в локальную SQLite разделена на порции до 500 строк / 15 мс, загрузка EhLib — на порции по 100 строк с бюджетом 15 мс. Они выполняются таймером UI, без передачи VCL/FireDAC в рабочий поток и без ProcessMessages внутри production-импорта. При отмене незавершённая транзакция откатывается, неполная выборка очищается и не выдаётся за полный результат. Перед окончательным показом доступны те же сортировка и фильтры. Диалог и завершение не могут повторно входить друг в друга через queued callback. Закрытие формы во время поиска запрашивает отмену; повторное закрытие доступно после неё.

Ключевые файлы: `SearchLimit.h`, `SearchGuardUI.h`, `SearchResponse.h`, `SearchGridLoader.h`, `Net/SearchRequestControl.h`, `Net/SearchCancellableIo.h`, `Net/MultiServerManager.h`, `Net/myAsioClient.*`, `formMain.*`, `TemplateSearch.h`, `TemplateFeedback.h`, `my_json/Request.h`, `my_json/ConverterJSON.cpp`.

## Статус и ограничения

Реализация включена в проверенный **локальный пакет 4.3.84**. Публикация, commit и push не выполнялись; рабочие файлы пользователя и облачные релизы не заменялись.

Отмена локальная: сервер может ещё завершать начатый SQL. Wire-команды остановки SQL и передачи точного общего count отсутствуют; они не вводились. «Без лимита» снимает ограничение числа документов, но сохраняются технические ограничения памяти/ответа и серверные ошибки. Это мягкий контроль ожидания, а не принудительное прерывание любого нативного вызова строго на 20-й секунде: отдельные операции SQLite и завершающие сортировка/фильтры EhLib выполняются внутри своих библиотек. Физический Windows 7, ручной полный GUI и реальные рабочие службы на этом этапе не проверялись.
