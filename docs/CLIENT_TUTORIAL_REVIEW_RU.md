## Проверка исходящих приложений

Проверены оба маршрута: общий пакет (`btnSaveClick` → `SaveFileIsh` → `copyFile/ExtZip`) и один файл через детали (`FrameAttachments.cpp` → `ExtractAttachmentToPath`).

- Архив объявляется сервером под именем `<номер>.zip`; клиент получает его с сервера-источника строки.
- В пакете задания архивов сгруппированы по `(serverId, telegramId)`, поэтому одинаковый номер разных серверов не смешивает запросы.
- Исходные имена делятся по `;`, позиция i сохраняет соответствие записи `MESSAGE/aps/make_msg/tmpvl00(i+1).srg`. Пропуск недопустимого имени не перенумеровывает последующие записи. Запись 0 — тело, 10 — `tmpvl0010.srg`.
- Пакет скачивает ZIP один раз на задание и извлекает перечисленные приложения. Панель одного файла тоже получает весь архив, извлекая выбранную позицию.
- Отметка «Да» у исходящих основана на наличии ZIP, без проверки его внутренних записей; размер отдельного приложения неизвестен до извлечения.
- Отсутствующая обязательная запись учитывается как ошибка; SaveFileIsh возвращает успех только при полностью успешной распаковке ожидаемых допустимых имён. Уже полученные файлы при частичной ошибке остаются.
- Пакет использует свободные имена `(n) имя`; один файл разрешает замену после диалога. Временные архивы штатно удаляются.
- Семантическая правильность порядка PrilName не проверяется: корректный ZIP с ошибочным порядком карточки может дать неверное имя содержимому. Это зависимость входных данных, описанная пользователю, без изменения кода.
