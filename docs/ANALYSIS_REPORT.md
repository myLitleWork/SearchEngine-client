## Сколько настроек найдено

Около **25+** пользовательски значимых параметров/групп:

- UI сеанса: IP, год, SQL, точное совпадение, тип, поле, лимит, OEM, регистр (скрыт), флажки сохранения, каталог, отдельная папка;
- файлы: необязательный legacy `SERVER_IP.INI`, `Templates.json`, `admin984.bin`, `sht.docm`;
- таблицы БД: `servers`, `server_ports`, `ports`, `settings.use_f12`, `map`/`map_vh`/`map_ish`;
- плюс зашитые таймауты (описаны как ненастраиваемые).

Точный «штучный» подсчёт зависит от того, считать ли каждое поле таблицы отдельной настройкой; в справочнике они сгруппированы по смыслу.

## Неясности и ограничения статического анализа

1. **Реальные ответы сервера** и полный набор серверных ошибок вне клиента не проверялись runtime smoke-тестом.
2. **Содержимое конкретной боевой `Settings.db3`** (список годов/портов/map) зависит от поставки; в документации описана схема и поведение кода.
3. **FastReport UI** после `ShowReport()` зависит от самого FastReport; детальные кнопки превью не проверялись интерактивно.
4. Поведение при одновременной работе нескольких экземпляров клиента с одной `Settings.db3` не проверялось.
5. Полный состав поставки ещё требует smoke-test на чистой машине; текущий обоснованный allowlist зафиксирован в `docs/RELEASE_PACKAGE.md`.

## Предположения (явно)

- Предполагаемый пользователь — сотрудник, работающий с учётом/поиском телеграмм в организации-заказчике (выведено из предметных терминов UI: Вх./Исх., подписной номер, разноска, ПДТВ, опись).
- Общий пакет включает `sht.docm`, начальную `Settings.db3` и канонический
  `admin984.bin`; рабочие настройки серверов задаются организацией отдельно.
- «Основной сервер» — первый endpoint после сортировки `sort_order` (подтверждено кодом).

## Принятые решения

1. Клиентская групповая ACL удалена вместе с `checkUser` и файлами групп.
   Проверку прав должен выполнять сервер; серверная реализация пока не
   подтверждена.
2. Форма, модель и конвертеры резолюций удалены как неактуальные. Старые
   wire-номера команд сохранены резервными.
3. Релиз формируется по allowlist. `sht.docm` хранится в Git и всегда
   копируется в пакет; пользовательская документация перенесена в `tutorials/`;
   настройки серверов задаются отдельно, а `admin984.bin` входит в пакет.
4. релиз содержит обезличенный шаблон `Settings.db3` с обязательными
   словарями; серверы и порты заполняются для конкретного контура;
   без канонических значений ничего автоматически не генерируется.
5. Реальный controlled-server smoke обязателен, но отложен до предоставления
   безопасного endpoint'а, disposable-конфигурации и тестовых данных.
6. Signed-token/RSA-авторизация временно отключена, но сохранена в исходнике под
   `#if 0` с пометкой о возможном возврате. Генерация RSA-ключей отключена.
   Текущий режим — наличие `admin984.bin` рядом с EXE. Путь переведён на Unicode
   WinAPI и проверен в глубокой кириллической папке.
7. Повреждённые сообщения `FramePdtv.cpp` заменены понятными нейтральными
   формулировками по фактическому контексту каждой ошибки.
8. Повторный Excel-экспорт исправлен: принадлежащий форме `frxXLSExport1`
   больше не удаляется, а его временно изменённые свойства восстанавливаются.

## Уровень уверенности по разделам

Локальная проверка после принятых изменений: Debug и Release — 0 ошибок,
многосерверный Debug self-test — код 0, verifier релизного пакета — успешно.
Подключение к реальному серверу и DOCX через Microsoft Word не выполнялись.

| Раздел | Уверенность | Комментарий |
|---|---|---|
| Назначение и основной поток | Высокая | Подтверждено UI + код |
| Подключение/авторизация | Высокая для локального пути | Заглушка проверена в Unicode-пути; серверный smoke ещё не выполнен |
| Поиск и многосерверность | Высокая | Код fan-out + существующий MULTI_SERVER doc |
| Просмотр текста/деталей | Высокая | Фреймы и обработчики сопоставлены |
| Сохранение файлов/DOCX | Высокая | btnSave и worker просмотрены |
| Отчёты/Excel | Средняя–высокая | Вызовы есть; UX превью FastReport не прогонялся |
| Шаблоны | Высокая | CRUD в JSON просмотрен |
| Загрузка/опись/разноска/приложения | Высокая | Обработчики просмотрены; серверная семантика «что именно означает разноска» предметно не уточнялась за пределами UI |
| Настройки БД | Высокая | Схема + UI вкладки |
| Резолюция | Решено | Функциональность удалена |
| Разграничение прав | Требование к серверу | Клиентская ACL удалена; сервер не проверен |
| Сообщения об ошибках ПДТВ | Высокая | Повреждённые строки заменены по контексту веток обработки |
| Поведение на конкретной сети/сервере | Не проверялось runtime | Только статический анализ |
